# 阶段一市场诊断框架

## 任务与输入

按顺序完成三层诊断：周期频谱定位 → 市场背景评估 → 逐 K 信号确认。三层必须互相核对，但阶段一不制定三价、不选择订单类型、不执行 §10.3 数值检验。

只使用当前快照和消息中的程序特征。K1 是最新已收盘 K 线，序号越大越早；K0 不在输入中，不得作为已发生依据。

## 分析窗口

设输入为 n 根 K 线，通常为 100；数据不足时使用实际存在的范围，不虚构窗口。

| 层级 | 窗口 | 用途 |
|---|---|---|
| 长程背景 | K{n}–K41 | `htf_context`、主要结构、支撑阻力和风险背景 |
| 近期结构 | K40–K1 | `cycle_position`、近期方向、通道/区间和状态转换 |
| 即时惯性 | K8–K1 | §2.3 当前方向、§2.4 Always In、§2.5 惯性和近端尖峰 |
| 即时信号 | K10–K1 | 信号候选、跟随、突破测试和二次结构 |
| 逐棒摘要 | K5–K1 | `bar_by_bar_summary`，窗口足够时恰好 5 条 |

长程背景可以在叙述上参考全窗口，但程序切分与 trace 必须遵守上表。长程方向不直接否决明确的近期方向；冲突写入 `trend_context` 和风险说明，置信度上限按程序规则执行。

## 第一层：周期频谱定位

输出一个主 `cycle_position`，边界模糊时用 `alternative_cycle_position` 记录第二可能状态。形态名称放入 `detected_patterns`，不能冒充周期状态。

### 1. 尖峰 `spike`

**可观察特征**：同方向强趋势棒连续推进，实体大、收盘靠近方向极点、重叠少、回撤极小，通常突破既有结构。成交量不是必要条件。

分级：

- **候选**：只有一根超大突破棒时标 `spike_candidate`，不得仅凭这一根输出主状态 `spike`；等待第二根及跟随。
- **最低可路由**：至少两根连续同方向大型趋势棒，实体重叠通常小于 30%，并持续创出方向极值。
- **标准**：约 3–5 根，重叠更少、影线较短、紧迫感明确。
- **高潮风险**：连续约 6 根以上进入预警；出现衰竭信号可触发高潮，不以根数单独确认反转。

`spike_stage`：尖峰主状态必填。`active`=仍在推进；`ending`=出现暂停、十字星或减弱但尚未确认转换；`transitioning`=尖峰已结束，按现有路由转向通道评估。反向棒是转换证据，不是自动反转交易信号。

### 2. 微型通道 `micro_channel`

约 2–10 根 K 线的高低点连续同向推进，几乎无回撤，允许不破坏结构的短暂停顿。若同一窗口已经满足尖峰最低标准，优先 `spike`，不重复作为主状态。

微型通道的第一次逆向突破可能失败并恢复原方向，但这只是顺势偏好，不是高胜率证明。`spike_stage` 在有明确尖峰背景时填写 `active/ending`，否则可为 null。

### 3. 窄/紧凑通道 `tight_channel`

已有有序波段和可画通道，最近有效回撤通常小于 30%；K 线重叠少、回撤短、EMA 接近价格。斜率和视觉宽度只作辅助。

### 4. 常规通道 `normal_channel`

已有有序波段和可画通道，最近有效回撤通常约 30%–50%，波段清晰且仍有顺势惯性。斐波那契刻度只是描述工具，不是独立支撑或概率依据。

### 5. 宽通道/台阶 `broad_channel`

最近有效回撤通常约 50%–78.6%，波段较大、重叠较多、突破后常见测试。至少需要三组有效 HH+HL 或 LL+LH，且可以画出大致稳定的通道线。

### 6. 趋势型交易区间 `trending_tr`

Brooks 的核心结构是**两个或更多由突破分隔的交易区间**，常形成台阶和方向偏好。两组 HH+HL/LL+LH、序列被打断或通道线不稳定只能作为辅助证据，不能替代“区间—突破—区间”。

它与宽通道相邻，但不应按强趋势在中部追单。若只有两组高低点而没有区间分隔或台阶证据，应在 `trading_range`/`broad_channel` 间保留备选并降低置信度，而不是强行命名趋势型区间。

### 7. 普通交易区间 `trading_range`

上下边界各有至少约两次有效测试，价格反复往返、K 线重叠、EMA 相对平坦。方向可以弱偏多或偏空；中性时不做双边计划。

### 8. 极端交易区间 `extreme_tr`

大量重叠、长影或十字星、EMA 水平纠缠、方向感丧失，任意入场接近噪声。综合定性判断，不设伪精确门槛；不要把普通区间过早升级为极端区间。此状态触发等待。

### 区间与通道统一裁决

1. 只有一组或没有连续 HH+HL/LL+LH：进入区间评估。
2. 两组序列：只作通道候选。若同时存在“区间—突破—区间”或台阶结构，可归 `trending_tr`；否则在普通区间/宽通道间保留备选并降低置信度。
3. 至少三组且能画稳定通道线：再按最近有效回撤深度划分窄、常规、宽通道。
4. 区间上下沿清晰且 EMA 近似水平：`trading_range`；极端混乱才是 `extreme_tr`。
5. 最新波段破坏原有序列时重新评估，不能仅凭一根刺穿宣布反转。

## 第二层：市场背景评估

### 五个维度

1. **方向**：EMA 方向、波段高低点、收盘重心和价格相对 EMA 的位置。背景可使用 20 根重心；当前 `direction` 以程序的 K8–K1 五信号投票为准。
2. **强度**：趋势棒比例、重叠、回撤持续时间、波段幅度、EMA 距离和反向跟随。远离 EMA 也增加均值回归风险，不能单向解读。
3. **阶段**：初期突破/尖峰、中期通道、末期高潮或衰竭。阶段是证据组合，不由运行时间单独决定。
4. **位置**：区间上/中/下三分之一、趋势线、前高低、缺口和支撑阻力。区间中部不作为入场依据。
5. **窗口关系**：同向可支持诊断；冲突时近期方向为主，长程作为风险，不虚构外部大周期。

### 趋势背景

- 初期：强突破和跟随支持顺势，但仍禁止追尖峰或高潮。
- 中期：回撤和通道边界是主要观察位置；通道可能表现为更大结构中的旗形，不等于必然反转。
- 末期：轨道线穿越、连续高潮、推进递减和反向跟随降低追单质量；反转仍需完整证据。

### 区间背景

- 上沿容易测试阻力，下沿容易测试支撑，但实际方案只允许顺 `direction`/Always In 一侧。
- 突破分为影线试探、收盘越界、快速失败、测试中和存活突破；不同层次不得共用概率。
- 存活突破需要收盘站稳和后续未快速收回。只有程序允许时才把区间 MM 作为主要远目标。

### 关键位置

- EMA、趋势线、前高低、区间边界是观察位，不是天然成交保证。
- 趋势线突破不等于趋势反转；还需观察原趋势恢复和极点测试。
- 突破后回测常见，不能仅凭回测判定成功或失败。
- 缺口必须区分开盘跳空与均线几何关系，不能由缺口单独推断趋势。

## 第三层：逐 K 信号确认

扫描 K10–K1，使用共享 K 线字典与程序几何表：

1. 分类每根 K 线，并核对程序 `bar_type`，不自行覆盖。
2. 区分结构棒、信号候选、入场候选、确认、测试、陷阱、高潮或噪声。
3. 检查后续一至两根跟随；K1 没有后续已收盘棒时通常为 `pending`。
4. 识别突破失败、突破测试、失败的失败、H1/H2/L1/L2、楔形、双顶底和最终旗形。
5. 只写诊断和待评估条件，不写具体订单三价。

`bar_by_bar_summary` 覆盖 K5–K1，每条对应一根 K 线并说明其增量作用。不得把 `mtr`、`h2` 等形态名写入 `role`。

## 路由与输出映射

- 周期、方向、尖峰阶段、备选状态和形态标签决定程序路由；`strategy_files_needed` 只是参考，不能覆盖程序。
- 多个形态可以共存，如 `wedge + reversal_attempt`、`final_flag + barbwire`。
- 使用 `_reference/pattern_enum.md` 的规定标签；无特殊形态时 `detected_patterns=[]`。
- `support_levels` 和 `resistance_levels` 必须相对最新收盘价有效，突破后更新，最多三项；无法识别时用空数组。
- `diagnosis_confidence` 是 0–100 整数，不是胜率。低置信度且没有关键信号时，阶段二应更谨慎但仍执行完整流程。
- `market_phase=transitioning` 时填写 `transition_risk`，并提高阶段二对弱信号和中部方案的审查。
- 增量模式如实填写序号平移、`incremental_delta` 和方案连续性所需信息，不伪造新增 K 线。

## 阶段一闸门

按动态消息要求执行 §1–§2，并尊重程序预填节点：

- 数据不足或质量不合格由前置闸门处理。
- 无法识别周期：`cycle_position=unknown`，闸门不通过。
- 极端混乱：`cycle_position=extreme_tr`，闸门不通过。
- 方向中性、惯性不足、窗口冲突或转换期本身不等于 `gate_result=wait`；若周期可识别则继续阶段二。
- `gate_trace` 的节点、答案、问题、`bar_range` 和最后说明遵循动态输出契约，不增加汇总节点或禁止行为扫描。

最终只输出消息规定的完整阶段一裸 JSON。所有字段以程序动态 Schema 和骨架为准，本文件不维护第二份 JSON 示例。
